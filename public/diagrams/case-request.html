  • User question: Conversation context clarifies the request; source knowledge is retrieved rather than pasted as an entire corpus.
  • Task requirements: An architecture comparison raises reasoning requirements. Tool and image needs are explicit requirements, not features to silently discard.
  • Eligible inventory: The selector excludes routes below the required quality tier or without required capabilities. Model labels and configured scores are assumptions, not benchmark results.
  • No eligible route: No lower-capability downgrade is substituted just to return an answer. One infrastructure fallback is allowed only among compatible routes before visible output.
  • Configured score: Among eligible routes, configured relative cost and latency contribute to the score. These are not measured savings or a learned optimizer.
  • Bounded graph: At most two independent tasks when requested. Three retrieval calls include grounding and memory; four logical model calls include branches, synthesis and repair. The shared budget survives continuations.
  • Search, then read: Retrieval uses BGE, Qdrant and prepared text. Reading a returned source establishes evidence; selecting a candidate alone does not prove attribution.
  • Supported answer: Return through the client protocol and persist checkpoints when storage is requested. Guarded answers may buffer. A partial stream never restarts on another provider.
